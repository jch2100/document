# 2. fill-pptx — 양식 PPT 채우기

## 순서

1. **양식 결정** (SKILL.md 2절). profile.yaml 의 `layouts`(슬롯 이름)와 `storyline` 확인.
2. **분량 결정**: 사용자가 말 안 하면 profile 의 `length` 범위. 원자료가 적으면 적게 — 빈 장을 만들지 않는다.
3. **고스트 덱 먼저 (텍스트로)**: 장마다 `레이아웃 | 트래커 | 제목(결론 문장)` 한 줄씩 목록을 만든다.
   - 제목만 이어 읽어도 보고 전체가 이해돼야 한다 (제목 테스트). 2장은 보통 요약(3단카드: 상황·발견·제언).
   - 제목은 주제어 금지("현황" ✗ → "이용률이 3년째 하락해 31%" ○).
   - 사용자가 "바로 만들어"가 아니면 이 목록을 먼저 보여 주고 진행해도 된다. 급하면 바로 진행.
4. **내용 JSON 작성** — `references/content-format.md`
   - 슬롯 이름은 profile.yaml 그대로 (예: `제목`, `핵심메시지`, `본문`, `좌측제목`, `카드1제목`, `표`, `차트`)
   - 본문은 목록. 하위 항목은 중첩 목록 `["항목", ["하위1", "하위2"]]`
   - 분량: profile 의 slot `limit` 을 지킨다. 본문 항목 3~6개, 한 항목 40자 안팎.
   - 숫자 비교 → `표` 또는 `차트` 레이아웃. 셋 나열 → `3단카드`. 전/후 → `2단비교`.
   - 원자료에 없는 숫자를 지어내지 않는다. 필요하면 `[확인 필요: ○○]` 로 남기고 보고 때 알린다.
5. **실행**
   ```
   python SKILL_DIR/scripts/fill.py --template pptx/01 --content 내용.json --out 결과.pptx --preview
   ```
6. **검증 대응** (자동 출력)
   - `overflow_high/maybe` → 그 슬롯 글을 줄이거나 장을 나눈다
   - `ending_style` → '~습니다' 를 '~함/~임/명사형'으로
   - `ai_tone` → 수식어 삭제, 숫자로 대체
   - `guide_left` → `[ ]` 안내문을 실제 내용으로
   - 고친 JSON 으로 다시 실행. 3회 안에 PASS 가 안 되면 남은 항목을 보고.
7. **미리보기 확인** (`*_pptx_preview/*-sheet.png` 를 직접 본다): 겹침, 빈 장, 너무 빽빽한 장. 미리보기는 LibreOffice 렌더라 실제 PowerPoint와 줄바꿈이 조금 다를 수 있다고 알린다.
8. **전달**: SKILL.md 5절 형식.

## 레이아웃 고르기 (기본 양식 기준, 자세히는 references/design-system.md 7절)

| 하고 싶은 말 | 레이아웃 |
|---|---|
| 전체 요약 (상황·발견·제언) | 3단카드 |
| 숫자 하나가 결론 | 빅넘버 |
| 추이·비교 + 그래서 뭐 | 차트 (`highlight` 로 막대 하나 강조) |
| 대안 비교·일정·R&R | 표 (`highlight_col` 로 추천안 강조) |
| 전/후, 문제/원인 | 2단비교 |
| 우선순위 | 매트릭스 |
| 추진 단계 | 프로세스 (4단계) |
| 설명·근거 | 본문 (다른 게 안 맞을 때만) |
| 결론 한 장·전환 | 핵심메시지 |
| 화면·구성도 | 이미지 (그림 파일이 있을 때만) |
| 장 구분 | 섹션 (15장 이상일 때만) |
| 요청·다음 단계 | 마무리 |

같은 레이아웃을 3장 넘게 연달아 쓰지 않는다 (본문만 이어지면 읽는 힘이 떨어짐).

# 4. revise — 결재 피드백 부분 수정

원칙: **전체를 다시 만들지 않는다.** 사람이 Word/PowerPoint에서 손댄 부분을 지키기 위해 지목된 곳만 바꾼다.

## 순서

1. **현재 내용 파악**: `python SKILL_DIR/scripts/extract.py 파일 --out 현재.json` → 슬라이드 번호·슬롯 이름·문단 텍스트 확인.
2. **피드백 → 작업 목록**으로 번역. 애매한 피드백은 해석을 한 줄로 밝힌다.
   - "3장 결론이 약해" → `{"slide":3, "slot":"핵심메시지", "value":"..."}` (해석: 숫자 근거를 앞으로)
   - "비용 근거 추가" → `{"insert_after":5, "spec":{"layout":"표", ...}}`
   - "요청사항을 앞으로" → `{"move":7, "to":2}`
   - Word: `{"find":"문단 일부", "replace":"새 문장"}`, `{"after":"기대 효과", "blocks":[{"b":["..."]}]}`
3. **실행**: `python SKILL_DIR/scripts/revise.py 원본 --ops 수정.json --out 원본_v2.pptx` (검증 자동)
4. **보고**: `*_변경내역.md` 내용 + 검증 결과. 버전은 `_v2`, `_v3` 로 쌓는다 (원본 덮어쓰기 금지).

## 피드백 유형별 처리

| 피드백 | 처리 |
|---|---|
| 표현·문장 | 해당 슬롯/문단 replace |
| 순서 | move |
| 근거 부족 | 표/차트 장 insert_after (원자료 없으면 `[확인 필요]`) |
| 너무 길다 | 항목 줄이기, 하위 항목으로 내리기 |
| 전체 방향이 틀림 | revise 가 아니라 새로 fill (사용자에게 확인) |

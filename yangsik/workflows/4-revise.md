# 4. revise — 결재 피드백 부분 수정

원칙: **전체를 다시 만들지 않는다.** 사람이 Word/PowerPoint에서 손댄 부분을 지키기 위해 지목된 곳만 바꾼다.

## 순서

1. **현재 내용 파악**: `python SKILL_DIR/scripts/extract.py 파일 --out 현재.json` → 슬라이드 번호·슬롯 이름·문단 텍스트 확인.
2. **피드백 → 작업 목록**으로 번역. 애매한 피드백은 해석을 한 줄로 밝힌다. `slot` 은 1번에서 확인한 **그 장의 칸 이름**.
   - "2장 결론이 길다" → `{"slide":2, "slot":"제목", "value":"..."}` (해석: 45자 → 30자로)
   - "대안 비교표에서 추천안 눈에 띄게" → `{"slide":5, "slot":"표", "value":{...현재 표 내용..., "highlight_col":2}}`
     (현재 표 내용은 extract 결과에서 복사 — 표·차트는 칸 전체를 새로 그림)
   - "차트 숫자 고쳐줘" → `{"slide":4, "slot":"차트", "value":{"type":"bar", "categories":[...], "series":{...}}}`
   - "비용 근거 추가" → `{"insert_after":5, "spec":{"layout":"표", ...}}`
   - "요청사항을 앞으로" → `{"move":7, "to":2}` / "이 장 빼" → `{"slide":6, "delete":true}`
   - Word: `{"find":"문단 일부", "replace":"새 문장"}`, `{"after":"기대 효과", "blocks":[{"b":["..."]}]}`
   - **슬라이드 번호는 모두 수정 전 파일 기준.** 작업 순서와 상관없이 1번에서 본 번호 그대로 쓴다.
   - 이미 강조된 걸 "더 눈에 띄게": ① 제목(액션 타이틀)에 추천안을 명시 ② 추천 열 칸에 `**굵게**` 핵심어 ③ 직전에 핵심메시지 장 추가("B안 추천: …") — 색·크기는 바꿀 수 없다
3. **실행**: `python SKILL_DIR/scripts/revise.py 원본 --ops 수정.json --out 원본_v2.pptx --preview` (검증 자동)
4. **확인 (필수)**: 출력의 `적용 N / 요청 M` 을 본다. `✗` 줄이 있으면 **그 요청은 반영되지 않은 것** — 고쳐서 다시 실행하거나, 못 한 것을 사용자에게 그대로 알린다. "모두 고쳤습니다"라고 하지 않는다.
5. **보고**: `*_변경내역.md` 내용 + 검증 결과 + 미리보기. 버전은 `_v2`, `_v3` 로 쌓는다 (원본 덮어쓰기 금지).

## 피드백 유형별 처리

| 피드백 | 처리 |
|---|---|
| 표현·문장 | 해당 슬롯/문단 replace |
| 표·차트 내용, 강조 | 슬롯에 표/차트 전체를 새로 지정 (`highlight_col`, `highlight`) |
| "더 눈에 띄게" | 표 `highlight_col`, 차트 `highlight`, 본문 `**굵게**` — 색·크기 직접 지정은 불가 |
| 순서 | move |
| 근거 부족 | 표/차트 장 insert_after (원자료 없으면 `[확인 필요]`) |
| 너무 길다 | 항목 줄이기, 하위 항목으로 내리기 |
| 전체 방향이 틀림 | revise 가 아니라 새로 fill (사용자에게 확인) |

## 다른 양식으로 옮기기 ("이 PPT를 우리 회사 양식으로")
1. `extract.py 기존.pptx --out 내용.json` (레이아웃 이름이 다르면 내용.json 의 layout 을 새 양식 이름으로 고친다: `python SKILL_DIR/scripts/list_templates.py`)
2. `fill.py --template <회사>/pptx/01 --content 내용.json --out 새.pptx --company "<회사명>"`
3. 양식 밖 텍스트(`_양식밖_텍스트`)는 알맞은 칸으로 옮기거나 버린다고 사용자에게 알린다
